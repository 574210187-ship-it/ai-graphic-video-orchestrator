# GitHub落地、下载和双引擎闭环路径

## 阶段A：干净仓库与离线合同

1. 建立独立仓库，不复制历史`runs/`、旧WorkBuddy链和真实配置。
2. 配置化飞书字段、Space路径、MD版本、视频包路径、背景与人物素材。
3. 实现实时发现、来源下载、任务清单、状态事件、租约、产物校验、附件上传和回读。
4. 使用fixture表和fixture控制器完成端到端离线测试。
5. 执行Skill验证、单元测试、Secret扫描、绝对路径扫描和大文件扫描。

通过标准：离线夹具能够从“未执行”变为“完成视频”，两个普通分支SHA不同，重新扫描为0；故障夹具会跳过失败行并继续。

## 阶段B：GitHub公开仓库

1. 初始化Git并提交脱敏代码。
2. 创建公开仓库`ai-graphic-video-orchestrator`；真实飞书资源标识只写入目标电脑的Git忽略配置。
3. 推送`main`。
4. 从另一个空目录重新clone，执行`bootstrap.sh`和全部离线测试。
5. GitHub Actions只运行离线测试和扫描，不接触飞书、ChatGPT或EGO。

通过标准：空目录安装不依赖原项目路径，没有任何密钥或`/Users/...`业务路径进入Git历史。

## 阶段C：DeepSeek Harness/Honey＋EGO受控测试

1. 在DeepSeek工具中clone仓库并安装Skill。
2. 复制本机私有配置，执行离线doctor。
3. 使用专用测试记录分别验证普通单页、普通多页和单页中心律师。
4. 每条测试完整执行：实时领取→下载来源→第0阶段→分支独立聊天生图→同聊天生视频→下载→上传飞书→状态/备注/执行记录→实时回读。
5. 验证单行失败后仍能继续下一行，重启后不重复已完成行。

通过标准：三种允许路线均通过，普通路线双视频SHA不同，飞书回读一致，最终测试队列为0。

## 阶段D：ChatGPT Work网页能力测试

1. Work从GitHub读取Skill和业务合同。
2. 验证能否原生创建、命名、继续和回收普通Chat子页面，并能上传对标页、追加原视频、下载最终MP4和保留聊天URL。
3. 若任一关键能力不成立，启用本地`work_child_bridge`；Work只负责决策与调度，桥接器负责本机文件、EGO和飞书。
4. 使用与Harness不同的专用测试记录重复三路线验收。

通过标准：Work方向不依赖人工搬运文件或复制长回复，也能完成飞书写回与回读；无法原生实现时，桥接模式必须真实接通，不能用提示词假装完成。

## 阶段E：生产清零

1. 确认唯一生产写入者。
2. 设置`production.enabled: true`和明确的生产作用域。
3. 每轮实时扫描两个条件的并集：先处理`二次分类型=图文`，再处理`类型=图文`且二次分类型为空或其他值的记录；两项同时满足只领取一次。
4. 分类命中后仍必须有唯一来源，且`成品`、`已发布`两列都没有视频；逐行执行，单行最多有界恢复，仍失败则入阻塞清单并继续。
5. 全部候选处理后重新从飞书第一页扫描到末页。
6. 只有可执行未完成数为0，且每个阻塞项都有错误码、record_id、证据和下一步，才可结束。

## 版本门禁

- `v0.1.0-rc1`：离线合同通过并上传GitHub；正式开放前完成全历史密钥扫描。
- `v0.1.0-rc2`：Harness/Honey三路线通过。
- `v0.1.0-rc3`：Work原生或桥接三路线通过。
- `v0.1.0`：双引擎各自从空目录安装成功，并完成生产前受控批次。
