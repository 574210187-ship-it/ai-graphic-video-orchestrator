# 姜律师图文候选行口径

## 长期默认口径

程序默认只领取同时满足以下条件的记录：

1. `二次分类型=图文`；
2. 按配置的来源优先字段查找后，恰有1个可用附件；
3. `成品`和`已发布`两列都没有视频附件；
4. 不以`状态`字段代替上述两列实物判定；
5. 真实下载后按文件魔数和媒体流判断类型，不信任扩展名。

## 2026-10-29一次性宽口径

当时用户明确授权把`类型=图文`且`二次分类型`为空的记录也纳入该批。实时初筛得到69行：

- 2行：`二次分类型=图文`；
- 67行：`类型=图文`且`二次分类型`为空。

这69行均满足：来源附件唯一，且`成品`、`已发布`两列均无视频。随后下载发现`reczz28OnI1YUWOE`虽命名为MP4，实际是纯MP3音频，因此可视候选为68行。

后续真正启动全量执行时，表格又发生了外部完成和实时状态变化，固定快照为64行。`69 → 68 → 64`是同一口径在不同时点的“初筛、真媒体验证、开工冻结”数字，不是三次随意换规则。

## 复用不改变行数

不同record_id的来源SHA-256完全相同时，可以在已验收的前提下复用成品，但每个目标行仍要独立上传、写回和实时回读。复用只减少网页生成，不减少待办记录数。

## 安全规则

宽口径只能在用户对当批明确授权时启用，不得因历史上有过一次授权就永久放宽。GitHub工具当前仍默认使用严格口径。
